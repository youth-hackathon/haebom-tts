# TTS 서버 팀 프롬프트: 내 컴퓨터에서 띄우고 재기

이 문서를 그대로 코딩 에이전트에게 줍니다. TTS 서버를 맡은 사람이 자기 컴퓨터에서 한 번 실행합니다. Docker가 없으면 `docs/docker.md`부터 합니다.

---

## 할 일

이 컴퓨터에서 TTS 서버를 띄우고, 검사 도구로 약속을 지키는지와 얼마나 빠른지를 잴 수 있게 합니다. 앱도 폰도 artemis 서버도 필요 없습니다.

끝나면 이 셋이 됩니다.

1. `http://127.0.0.1:8766/health`가 답한다.
2. `python check.py`가 약속 검사를 모두 통과하고, 문장마다 걸린 시간과 소리 파일을 남긴다.
3. 엔진을 고치고 다시 재서 숫자와 소리를 비교할 수 있다.

## TTS 서버가 지킬 약속

앱이 기대하는 것은 이것뿐입니다(`docs/interface.md`의 "앱과 TTS 서버"). 서버 안은 마음대로 바꿔도 됩니다.

- `POST /tts`에 `{"text": "문장", "speed": 0.9}`를 보내면 200과 소리를 돌려줍니다. `speed`는 없을 수도 있습니다. 앱은 코드가 정확히 200일 때만 소리로 봅니다.
- 응답의 `Content-Type`은 `audio/`로 시작하고, 안드로이드가 바로 재생할 수 있는 형식입니다(wav, mp3, ogg, m4a). 앱은 받은 것을 확장자 없는 파일로 저장해 재생하므로, 형식은 내용만으로 알아볼 수 있어야 합니다. WAV로 줄 때는 파일 머리의 길이 값이 실제 길이와 맞아야 합니다.
- 빈 문장이나 JSON이 아닌 요청에는 4xx로 답합니다.
- `GET /health`는 200과 JSON으로 답합니다.
- 여러 문장이 동시에 와도 모두 답합니다.
- 앱은 문장을 보내고 **1.5초**를 기다립니다. 그 안에 소리가 끝까지 다 오지 않으면 폰에 든 음성으로 읽고, 늦게 온 소리는 버립니다. 앱은 소리를 다 받은 뒤에 재생을 시작하므로, 앞부분만 먼저 보내는 것은 도움이 되지 않습니다. 서버의 음성이 실제로 쓰이려면 처음 요청한 문장이 1.5초 안에 다 와야 하고, 폰에서는 여기에 통신 시간이 더해집니다. 연결은 1초, 응답은 5초까지 기다립니다.
- 같은 문장과 속도에는 같은 소리를 줘도 됩니다. 만든 소리를 저장해 두고 다시 쓰면 두 번째부터 빨라집니다.
- 서버는 엔진을 여럿 가지고 요청의 `engine`으로 고릅니다. `baseline` 엔진은 언제나 있어야 합니다. 없는 이름에는 400으로 답합니다.

## 지킬 것

- 위의 약속을 바꾸지 않습니다. 바꿔야 하면 사람에게 알립니다.
- 외부 음성 서비스를 쓰게 되면 그 키는 환경 변수로만 넣습니다. 출력하지 않고 커밋하지 않습니다.
- 모르는 것은 추측해서 진행하지 말고 사람에게 묻습니다.

## 1. 준비물 확인

- `docker version`, `docker compose version`: 안 되면 `docs/docker.md`를 먼저 합니다.
- `git --version`
- `python --version`: 3.10 이상. 검사 도구는 파이썬 표준 라이브러리만 씁니다.

## 2. 저장소

- `https://github.com/youth-hackathon/haebom-tts`를 받습니다. 이미 있으면 최신으로 맞춥니다.
- 아래가 있는지 봅니다. 없는 것이 있으면 무엇이 없는지 알리고 멈춥니다(서버가 아직 없으면 `docs/prompt.md`가 먼저입니다).

| 있어야 하는 것 | 무엇 |
|---|---|
| `main.py` | TTS 서버. 소리를 만드는 곳은 함수 하나입니다 |
| `Dockerfile`, `docker-compose.yml` | 서버를 띄우는 방법. 서비스 이름은 `tts`, 포트는 8766 |
| `check.py` | 약속 검사와 벤치마크 |
| `sentences.txt` | 벤치마크에 쓰는 문장. 실제 안내 문장과 완료 문장 30개 |

## 3. 서버 띄우기

```bash
docker compose up -d --build tts
```

`http://127.0.0.1:8766/health`가 답하면 떴습니다. `engines`에 서버가 가진 엔진이, `default_engine`에 기본 엔진이 나옵니다. 로그는 `docker compose logs -f tts`로 봅니다.

## 4. 재기

```bash
python check.py
```

두 가지를 합니다.

- **약속 검사**: 위의 약속을 하나씩 확인합니다. 줄마다 통과, 실패, 경고가 나옵니다. 실패가 하나라도 있으면 종료 코드가 1입니다.
- **벤치마크**: 문장마다 처음 요청에 걸린 시간, 다시 요청했을 때의 시간, 소리 길이, 크기를 잽니다.

볼 것은 이 순서입니다.

1. 약속 검사에 실패가 없는가.
2. "1.5초 안에 온 문장"이 전부인가. 아니면 그 문장들은 앱에서 폰 음성으로 읽힙니다.
3. 결과 폴더(기본 `runs/tts-check/`)에 남은 소리 파일을 **직접 들어 봅니다**. 알아듣기 쉬운지, 숫자와 기호가 든 문장("글자 크기가 커졌어요 (1 → 1.15).")을 어떻게 읽는지는 들어야 압니다. 같은 폴더의 `result.csv`에 문장별 숫자가 있습니다.

옵션입니다.

- `--engine <이름>`: 그 엔진을 잽니다. `baseline`은 항상 됩니다. 주지 않으면 서버의 기본 엔진입니다.
- `--url <주소>`: 다른 곳에 떠 있는 서버를 잽니다.
- `--out <폴더>`: 결과를 둘 곳. 엔진마다 다른 폴더에 두면 소리를 나란히 들어 볼 수 있습니다.
- `--limit 5`: 앞의 다섯 문장만 잽니다.
- `--no-bench`: 약속 검사만 합니다.

참고로 확인용 엔진(espeak-ng)은 약속 검사 10개를 모두 통과하고, 처음 요청이 중앙값 20ms, 최대 27ms였습니다. 소리는 기계음입니다.

## 5. 고치고 다시 재기

```bash
# 1. main.py에 새 엔진을 자기 이름으로 더한다(baseline은 그대로 둔다). 설치는 Dockerfile에 넣는다
docker compose up -d --build tts                            # 2. 다시 띄운다
python check.py --engine <이름> --out runs/<이름>            # 3. 재고 듣는다
python check.py --engine baseline --out runs/baseline       #    베이스라인과 나란히 듣는다
```

- 서버를 다시 띄우면 저장해 둔 소리가 비워지므로 "처음 요청" 시간이 다시 재집니다.
- 문장을 더 넣고 싶으면 `sentences.txt`에 한 줄에 하나씩 더합니다.
- 엔진의 모델 파일이 크면 이미지를 만들 때 받아 두고, 서버가 뜰 때 미리 읽어 둡니다. 그러지 않으면 첫 문장이 느립니다.
- 그래픽 카드 없이 1.5초 안에 되는지는 재 봐야 압니다. 안 되면 더 가벼운 엔진을 쓰거나, 자주 나오는 문장을 미리 만들어 둡니다.

## 안 될 때

| 증상 | 볼 것 |
|---|---|
| 8766 포트를 이미 쓰고 있다고 나온다 | 다른 서버가 떠 있는지. 하나를 끕니다 |
| 검사 도구가 서버에 닿지 못한다 | `docker compose ps`로 `tts`가 떠 있는지, `docker compose logs tts --tail 20` |
| "소리가 재생할 수 있는 형식이다"에서 실패 | WAV의 길이 값. 소리를 흘려보내는 엔진은 머리에 길이를 0이나 최댓값으로 적습니다. 다 만든 뒤 실제 길이로 고쳐 씁니다 |
| 한글이 깨진다 | `python -X utf8 check.py` |

## 끝나면 알려 줄 것

- `/health`의 답(엔진 이름)
- 약속 검사의 실패와 경고 수
- 처음 요청의 중앙값과 최대, 1.5초 안에 온 문장 수
- 소리 파일이 있는 폴더
- 사람이 직접 한 일과 남은 일
